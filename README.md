## Описание задания

Лабораторная работа devoted анализу сетевого трафика и протоколов на базе **Wireshark**. Задачи:

1. Запустить Wireshark на захват, открыть веб-страницу (bstu.by, iit.bstu.by и др.), остановить и сохранить захват. Получить статистику: соотношение протоколов, средняя скорость кадров/ байт в секунду, мин/макс/средний размер пакета, загрузка канала.
2. Отфильтровать IP-пакеты, получить статистику по стеку TCP/IP, показать структуру заголовков Ethernet и IP на примере пакета.
3. Запустить захват, выполнить `ping` соседней рабочей станции, отфильтровать ICMP-пакеты, интерпретировать результат, составить диаграмму взаимодействия.
4. Запустить захват, запустить **TCP-сервер и TCP-клиент** (разработанные в предыдущей лабораторной работе), отфильтровать сеанс, показать структуру TCP-сегмента, составить диаграмму взаимодействия.
5. Запустить захват, запустить **UDP-сервер и UDP-клиент**, отфильтровать сеанс, показать структуру UDP-датаграммы.
6. Проанализировать протокол **ARP** по примеру из методических указаний.

## Пошаговый план демонстрации (как открыть и куда нажимать)

Ниже — полный порядок действий, чтобы показать работу всего комплекса на защите.

### Этап 0. Подготовка (сделать один раз)

1. Установить **Wireshark** (при установке оставить галочку на установку **Npcap** — драйвера захвата пакетов).
2. Склонировать репозиторий:
   ```
   git clone https://github.com/Anastasia1Kulick/AIPOS_II28.git
   cd AIPOS_II28
   ```
3. Убедиться, что Java компилируется (в папке `lab1,2`):
   ```
   javac -d . TcpServer.java TcpClient.java UdpServer.java UdpClient.java
   ```

### Этап 1. Запуск Wireshark и захват веб-трафика (задание 1–2)

1. Запустить **Wireshark**: Пуск → Все программы → Wireshark (или дважды кликнуть по ярлыку на рабочем столе).
2. Нажать кнопку **Capture Options** (инструмент «Опции…» / меню Capture → Options…).
3. В окне настроек захвата:
   - Выбрать **физический** сетевой адаптер (не виртуальный), тип интерфейса `Local`.
   - Поставить галочки:
     - ☑ Capture packets in promiscuous mode
     - ☑ Update list of packets in real time
     - ☑ Automatic scrolling in live capture
     - ☑ Enable MAC name resolution
     - ☑ Enable network name resolution
4. Нажать кнопку **Start** — начнётся захват трафика (появится информационное окно захода).
5. Открыть браузер и перейти на страницу `http://bstu.by` (или `http://iit.bstu.by`).
6. После загрузки страницы вернуться в Wireshark и нажать кнопку **Stop** (красный квадрат) — остановить захват.
7. Сохранить захват: меню **File → Save As…**, выбрать имя файла (например, `web_capture.pcapng`).
8. **Статистика** (задание 1):
   - Меню → **Statistics → Summary** — общее число пакетов, средняя скорость.
   - Меню → **Statistics → Protocol Hierarchy** — процентное соотношение трафика по протоколам.
   - В同上 окне можно увидеть среднюю скорость кадров/сек и байт/сек, мин/макс/средний размер пакета, загрузку канала.
9. **Фильтрация IP-пакетов** (задание 2):
   - В поле фильтра (вверху основного окна, строка «Filter:») ввести: `ip`
   - Нажать кнопку **Apply** (поле окрасится зелёным).
   - Останутся только IP-пакеты.
   - Повторить пункты статистики (Statistics → Summary / Protocol Hierarchy) для отфильтрованного набора.
   - Нажать **Reset**, чтобы сбросить фильтр.
10. **Структура Ethernet и IP**:
    - Выделить любой IP-пакет в списке (клик левой кнопкой мыши).
    - В среднем окне раскроется иерархия протоколов: **Frame → Ethernet → IP → (TCP/UDP/…)**.
    - Развернуть **Ethernet II**: показать поля `Destination` (MAC получателя), `Source` (MAC отправителя), `Type` (0x0800 = IPv4).
    - Развернуть **Internet Protocol (IP)**: показать поля `Version`, `Header length`, `Differentiated Services Field`, `Total Length`, `Identification`, `Flags`, `Fragment offset`, `Time to live`, `Protocol`, `Header checksum`, `Source`, `Destination`.
    - Интерпретировать значения полей (см. методичку netWS.pdf, разделы Ethernet / IP).

### Этап 2. Анализ команды ping (задание 3)

1. Определить IP-адрес соседней рабочей станции: в командной строке выполнить `ipconfig`, посмотреть адрес соседа (или использовать шлюз).
2. Очистить ARP-кэш: `arp -d <IP соседа>`.
3. В Wireshark запустить новый захват ( кнопка **Start** ), в поле фильтра захвата (Capture Options → Capture Filter) ввести: `arp or icmp` (или оставить пустым, чтобы захватить всё, а потом отфильтровать).
4. Нажать **Start**.
5. В командной строке выполнить: `ping <IP соседа>` (например, `ping 192.168.1.5`).
6. После получения ответов остановить захват (кнопка **Stop**) и сохранить (File → Save As… → `ping_capture.pcapng`).
7. Применить дисплей-фильтр: в поле «Filter:» ввести `icmp` → нажать **Apply**.
8. Выделить пакет **Echo request** — в среднем окне показать протоколы: **Frame → Ethernet → IP → ICMP**. Поля ICMP: `Type` (8 = запрос), `Code` (0), `Checksum`, `Identifier`, `Sequence number`.
9. Выделить пакет **Echo reply** — поле ICMP `Type` (0 = ответ).
10. Интерпретация: время отклика (Time), TTL, потеря пакетов (0% при успешном соединении).
11. **Диаграмма взаимодействия**: меню → **Statistics → Flow Graph…** → выбрать ICMP → просмотреть диаграмму «запрос → ответ» между двумя машинами.
12. Протоколы, используемые ping: **ICMP** (RFC 792, RFC 960) поверх **IP**, поверх **Ethernet**.

### Этап 3. TCP-сервер и TCP-клиент (задание 4)

Нужно открыть **два окна командной строки** (одно для сервера, одно для клиента).

**Терминал 1 — TCP-сервер:**
1. Перейти в папку `lab1,2`.
2. Запустить: `run_tcp_server.bat` (или `java -cp . TcpServer`).
   - Сервер откроет порт `8080` и будет ждать подключений.

**Терминал 2 — TCP-клиент:**
3. Перейти в папку `lab1,2`.
4. Запустить: `run_tcp.bat` или `java -cp . TcpClient` — откроется графическое окно TCP-клиента.
5. В поле ввода клиента набрать: `connect 127.0.0.1 8080` и нажать **Tab** (или Enter).
   - В области вывода появится «Подключено к 127.0.0.1:8080» и приветствие сервера «Hello, Student!».
6. Набрать любую строку (например, `HelloServer`) и нажать **Tab** — клиент отправит строку, сервер вычислит контрольную сумму и ответит `Checksum: <сумма>`.

**Wireshark (параллельно):**
7. Запустить захват в Wireshark (кнопка **Start**), фильтр захвата можно оставить пустым.
8. Выполнить шаги 5–6 (подключение и отправка строки).
9. Остановить захват (кнопка **Stop**), сохранить (`tcp_capture.pcapng`).
10. Применить дисплей-фильтр: в поле «Filter:» ввести `tcp.port == 8080` → нажать **Apply**.
11. Выделить любой TCP-сегмент — в среднем окне показать протоколы: **Frame → Ethernet → IP → TCP**.
12. Развернуть **Transmission Control Protocol**: показать поля `Source port`, `Destination port`, `Sequence number`, `Acknowledgement number`, `Header Length`, `Flags` (SYN, ACK, FIN, PSH и др.), `Window size`, `TCP Checksum`, `Urgent Pointer`.
13. Показать установление соединения (three-way handshake): пакеты с флагами **SYN**, **SYN+ACK**, **ACK**.
14. **Диаграмма взаимодействия**: меню → **Statistics → Flow Graph…** → выбрать TCP → просмотреть диаграмму обмена между клиентом и сервером.
15. Нажать **Reset** для сброса фильтра.

### Этап 4. UDP-сервер и UDP-клиент (задание 5)

**Терминал 1 — UDP-сервер:**
1. Перейти в папку `lab1,2`.
2. Запустить: `run_udp_server.bat` (или `java -cp . UdpServer`).
   - Сервер откроет порт `667` на `127.0.0.1`.

**Терминал 2 — UDP-клиент:**
3. Перейти в папку `lab1,2`.
4. Запустить: `run_udp_client.bat` (или `java -cp . UdpClient`) — откроется графическое окно UDP-клиента.
5. В поле ввода набрать строку (например, `HelloUDP`) и нажать **Tab**.
   - Клиент отправит датаграмму серверу, сервер ответит `Checksum: <сумма>`.
   - В области вывода клиента появится ответ `< Checksum: ...`.

**Wireshark (параллельно):**
6. Запустить захват в Wireshark (кнопка **Start**).
7. Выполнить шаг 5 (отправка строки).
8. Остановить захват (кнопка **Stop**), сохранить (`udp_capture.pcapng`).
9. Применить дисплей-фильтр: в поле «Filter:» ввести `udp.port == 667` → нажать **Apply**.
10. Выделить любую UDP-датаграмму — в среднем окне показать: **Frame → Ethernet → IP → UDP**.
11. Развернуть **User Datagram Protocol**: показать поля `Source Port`, `Destination Port`, `Length`, `Checksum`.
12. Показать, что UDP — без установи соединения (нет handshake, как в TCP).
13. Нажать **Reset** для сброса фильтра.

### Этап 5. Анализ протокола ARP (задание 6)

1. Очистить ARP-кэш: в командной строке `arp -d <IP целевой машины>`.
2. В Wireshark запустить захват с фильтром захвата `arp or rarp` (Capture Options → Capture Filter → `arp or rarp`) → кнопка **Start**.
3. В командной строке выполнить `ping <IP целевой машины>`.
4. Остановить захват (кнопка **Stop**), сохранить (`arp_capture.pcapng`).
5. Применить дисплей-фильтр: `arp` → нажать **Apply**.
6. Должны появиться два пакета: **ARP request** и **ARP reply**.
7. Выделить ARP-запрос — показать поля: `Sender MAC address`, `Sender IP address`, `Target MAC address` (00:00:00:00:00:00), `Target IP address`, `Opcode: request (1)`, `Destination: ff:ff:ff:ff:ff:ff` (широковещательный MAC Ethernet).
8. Выделить ARP-ответ — показать поля: `Opcode: reply (2)`, `Sender MAC address` (MAC целевой машины), `Sender IP address` (IP целевой машины), `Target MAC address` (MAC отправителя запроса).
9. Проверить ARP-кэш после эксперимента: `arp -a` — должна появиться запись с MAC-адресом целевой машины.
10. Интерпретация: ARP преобразует IP-адрес в MAC-адрес (RFC 826), широковещательный запрос → unicast-ответ.
